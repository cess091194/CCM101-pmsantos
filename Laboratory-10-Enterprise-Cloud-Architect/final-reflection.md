# Final Reflection

When I started Mission 1, I didn't know much about the Linux terminal. Git and GitHub confused me, and I was just following the steps one by one. After ten missions, I can set up and manage a server on my own, and cloud computing makes a lot more sense to me now.

In Mission 2, I learned how to check a server's CPU, storage, and network, while in Mission 3, I learned that AWS, Azure, and GCP have almost the same services, and that the best one depends on what the client needs. Mission 4 helped me understand why containers are lighter and faster than virtual machines. In Mission 5, I got to see how object storage works for the first time with MinIO. Then in Mission 6, Docker Compose showed me that a whole setup can be written in one file and started again anytime.

Checking the health of a server and its containers was something I only learned to do properly in Mission 7. Protecting a server with a firewall came after that, and it taught me why the order of the steps matters. Scripts and scheduled jobs were the highlight of Mission 9, because routine tasks could finally run by themselves, although I also saw how risky automation can be when there is a mistake. Mission 10 put everything together. We built an Ubuntu Server VM in VirtualBox, deployed WordPress and MariaDB with Docker Compose, set up a Default Deny firewall, and scheduled a nightly database backup. The hardest part was making all of it work together. When something broke, read the error, checked the logs, and looked for another way instead of guessing.

The biggest thing I learned is that small details matter. A wrong space in a YAML file, the order of firewall commands, or the wrong folder can break the whole setup. I also learned that writing good documentation is part of the work, so that someone else can understand and repeat what I did. My GitHub portfolio now shows my progress, from simple Linux notes in Mission 1 to a full server project in Mission 10.
